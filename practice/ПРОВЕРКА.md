# Проверка учебных материалов

Дата: 17 сентября 2026 года. Основная проверка выполнена на Docker-стенде из этого каталога: **RabbitMQ 4.1.8, Erlang 27.3.4.17, Pika 1.3.2, Python 3.14.0**.

## Подтверждено запуском

- Один узел и кластер из трёх узлов; создание пользователя и permissions.
- Bash-функции HTTP API: declaration, binding, публикация, чтение.
- Direct, fanout, topic (вся таблица маршрутизации), headers, alternate exchange.
- TTL → DLX, overflow drop-head и reject-publish, classic priority.
- Publisher confirms, mandatory/unroutable, повторная доставка после закрытия connection без ack.
- Реальные `topology.py`, `publish.py`, `consumer.py`: переход в retry.10s, возврат и успешная обработка на attempt=1.
- `topology.py --quorum`: три фактических участника ha.work.
- Остановка лидера ha.work: через HAProxy прочитаны все 20 ранее подтверждённых сообщений и одно новое, отправленное после отказа; остановленный узел возвращён.
- TLS: клиент проверил CA и имя сервера, выполнил persistent publish с confirm и manual-ack get. Сертификаты совместимы со строгой проверкой Python 3.14.
- Stream: повторное чтение прежней записи при втором запуске клиента.
- Dynamic Shovel и Static Shovel: сообщения получены отдельным брокером remote.
- Queue Federation: реальный consumer на remote получил и подтвердил сообщение upstream.
- Exchange Federation: сообщение получено downstream очередью с заголовком x-received-from.
- Prometheus: все 7 targets UP; Ready, Unacked и ack counter действительно присутствуют.
- Telegraf: доступ к Management API ограниченной учётной записью monitoring; сбор overview/node/queue/exchange.
- Promtool: конфигурация и три alert rules корректны. Amtool и HAProxy: конфигурации корректны.
- Экспорт definitions vhost, импорт topology в новый `/restore`: объекты появились без сообщений; временный vhost удалён.
- Policy quorum DLX с at-least-once принята брокером.
- Alertmanager → локальный webhook: фактически получены firing и resolved.

## Границы проверки

**Пакетные установки apt/dnf/yum на отдельных VM не запускались.** Их последовательность и репозитории сверены с официальной документацией, доступность конкретных пакетов необходимо проверять на выбранной ОС.

**Все действия мышью в UI не автоматизировались.** Описаны соответствующие разделы и поля; в разных версиях UI подписи могут отличаться. Изменение topology и проверка доставки выполнялись через реальные API/AMQP.

**Это функциональная проверка учебного стенда, не нагрузочный тест и не доказательство production SLA.** Три контейнера находятся на одном физическом хосте. Проверка retry выполняет 10-секундный путь; полный 370-секундный цикл до parking разбирается в лаборатории отдельно.

## Статическая проверка

Проверены синтаксис Bash-блоков руководства и шпаргалки, Python-файлов и вставок, ссылки на локальные файлы и якоря оглавления, Compose-конфигурации основного стенда, Static Shovel и TLS.

После проверки созданные для неё контейнеры и volumes удалены, чтобы самостоятельное прохождение начиналось с пустого стенда. Образы Docker и локальное Python-окружение оставлены для повторного запуска.
